# 그래프 기본 탐색(DFS/BFS) & 자료구조 시간복잡도 총정리

## 1. 그래프 기본 개념 정리

### 1-1. 그래프란?

![][1.png]
![][weight.png]

-   **정점(Vertex)**: 노드(node)라고도 하며, 데이터가 저장되는 단위. 예시: (0, 1, 2, 3)
-   **간선(Edge)**: 정점(노드)들을 연결하는 선 link, branch라고도 부름.
-   **인접 정점(Adjacent Vertex)**: 간선에 의해 직접 연결된 정점. (예: 0과 2는 인접 정점)
-   **단순 경로(Simple Path)**: 경로 중 반복되는 정점이 없는 경우. 한붓그리기처럼 같은 간선을 두 번 지나지 않는 경로. (예: 0 → 3 → 2 → 1은 단순 경로)
-   **차수(Degree)**: 무방향 그래프에서 하나의 정점에 인접한 정점(간선)의 수. (예: 0의 차수는 3)
-   **진출 차수(Out-degree)**: 방향 그래프에서 외부로 향하는(나가는) 간선의 수
-   **진입 차수(In-degree)**: 방향 그래프에서 외부에서 들어오는(들어오는) 간선의 수
-   **경로 길이(Path Length)**: 경로를 구성하는 데 사용된 간선의 수
-   **사이클(Cycle)**: 단순 경로의 시작 정점과 종료 정점이 동일한 경우
-   **가중치(Weight)**: 간선에 부여된 비용

### 1-2. 그래프 표현 방법

![][2.png]

-   **G1 (무방향 그래프)**

    -   정점 집합: V(G1) = {0, 1, 2, 3}
    -   간선 집합: E(G1) = {(0, 1), (0, 2), (0, 3), (1, 2), (2, 3)}

-   **G2 (무방향 그래프)**

    -   정점 집합: V(G2) = {0, 1, 2, 3}
    -   간선 집합: E(G2) = {(0, 1), (0, 2)}

-   **G3 (방향 그래프)**

    -   정점 집합: V(G3) = {0, 1, 3}
    -   간선 집합: E(G3) = {<0, 1>, <1, 0>, <1, 2>}

-   **연결 그래프(Connected Graph)**
    -   모든 정점이 서로 연결되어 있는 그래프
-   **비연결 그래프(Disconnected Graph)**

    -   모든 정점이 서로 연결되어 있지 않은 그래프

-   **완전 그래프(Complete Graph)**

    -   모든 정점이 서로 연결되어 있는 그래프

-   **순환 그래프 (Cyclic Graph)**

    -   단순 경로에서 시작 정점과 도착 정점이 동일한 그래프

    ![][cyclic.png]

-   **비순환 그래프 (Acyclic Graph)**

    -   그래프에 사이클이 없는 그래프

### 1-3. 인접 행렬(Adjacency Matrix)

![][3.png]
![][3-1.png]

정점의 개수가 n이라면 n\*n 형태의 2차원 배열이 인접 행렬로 사용된다.
인접 행렬에서 행과 열은 정점을 의미하며, 각각의 원소들은 정점 간의 간선을 나타낸다.

-   V×V 2차원 배열 사용
-   `matrix[u][v] = 1` (또는 가중치) 이면 간선 존재
-   공간 복잡도: **O(V²)**

    -   엣지의 개수와 상관없이 항상 정점의 제곱만큼의 메모리를 차지합니다

-   **장점**

    -   2차원 배열에 모든 정점들의 간선 정보가 있기 때문에, 두 정점을 연결하는 간선을 조회할 때 O(1) 시간복잡도로 가능하다.
    -   정점(i)의 차수를 구할 때는 다음과 같이 인접행렬(M)의 i번째 행의 값을 모두 더하면 되므로 O(n)의 시간복잡도를 가진다.

-   **단점**
    -   간선의 수와 무관하게 항상 n² 크기의 2차원 배열이 필요하므로 메모리 공간이 낭비된다.
    -   그래프의 모든 간선의 수를 알아내려면 인접행렬 전체를 확인해야 하므로 O(n²)의 시간이 소요된다.

### 1-4. 인접 리스트(Adjacency List)

![][4.png]
![][4-1.png]

-   각 정점마다, "이어져 있는 정점 목록"을 저장
-   예) `graph[u] = [v1, v2, ...]`
-   공간 복잡도: **O(V + E)**

-   **장점**

    -   어떤 정점 `u`에 인접한 정점들을 탐색하는 데 **O(deg(u))** 시간이면 충분하다.  
        (여기서 `deg(u)`는 정점 `u`의 차수)
    -   그래프 전체를 한 번 DFS/BFS로 순회할 때 **O(V + E)** 시간이 걸린다.
    -   간선이 많지 않은 **희소 그래프**에서 공간 복잡도가 **O(V + E)**라서,  
        **O(V²)** 공간을 쓰는 인접 행렬에 비해 메모리 낭비가 적다.

-   **단점**
    -   두 정점 `u`, `v`가 직접 연결(간선 존재)되어 있는지 확인하려면  
        정점 `u`의 인접 리스트를 확인해야 하므로 **O(deg(u)) (최악 O(V))** 시간이 걸린다.  
        → 인접 행렬은 이 연산이 **O(1)**라서, 이 부분에서는 인접 리스트가 느리다.

> DFS/BFS는 **대부분 인접 리스트**를 기준으로 설명·구현하는 경우가 많음.

---

| 연산 / 특성       | 인접 행렬 (Adjacency Matrix) | 인접 리스트 (Adjacency List) |
| ----------------- | ---------------------------- | ---------------------------- |
| 공간 복잡도       | $O(V^2)$                     | $O(V + E)$                   |
| 정점 추가         | $O(V^2)$                     | $O(1)$                       |
| 정점 삭제         | $O(V^2)$                     | $O(V + E)$                   |
| 엣지 추가         | $O(1)$                       | $O(1)$                       |
| 엣지 삭제         | $O(1)$                       | $O(E/V)$ 또는 $O(V)$         |
| 두 정점 연결 확인 | $O(1)$                       | $O(\text{Degree})$           |

## 2. DFS (Depth-First Search, 깊이 우선 탐색)

### 2-1. 핵심 아이디어

-   **“끝까지 갔다가, 막히면 뒤로 돌아오기”**
-   한 정점에서 시작 → 가능한 한 깊숙이 내려감 → 더 갈 곳이 없으면 **되돌아(backtrack)**
-   구현 방식
    -   **재귀(Recursion)** 사용
    -   또는 **명시적 스택(Stack)** 사용

![[5.gif]][5.gif]

### 2-2. DFS 의사코드 (인접 리스트 기준)

```python
# graph: 인접 리스트 (0 ~ n-1 정점)
# visited: 방문 여부를 저장하는 배열 / 집합

def dfs(start):
    visited = set()
    _dfs_recursive(start, visited)

def _dfs_recursive(u, visited):
    visited.add(u)
    print(u)  # 방문 시 처리 (출력, 누적, 탐색 등)

    for v in graph[u]:
        if v not in visited:
            _dfs_recursive(v, visited)
```

## 2-3. 스택으로 구현한 DFS (반복형)

```python
def dfs_iterative(start):
    visited = set()
    stack = [start]

    while stack:
        u = stack.pop()
        if u in visited:
            continue

        visited.add(u)
        print(u)  # 방문 시 처리

        # 역순으로 push하면 방문 순서 조정 가능
        for v in reversed(graph[u]):
            if v not in visited:
                stack.append(v)
```

---

## 2-4. DFS 시간·공간 복잡도

-   **시간 복잡도:**
    -   인접 리스트 사용 시: $O(V + E)$
        -   모든 정점은 한 번씩 방문(visited 체크)됩니다: $O(V)$.
        -   각 정점을 방문할 때마다 그 정점에 연결된 간선들을 순회합니다. 모든 간선은 (방향 그래프 기준) 한 번씩, (무방향 그래프 기준) 두 번씩 확인됩니다. 이는 전체 간선의 수에 비례합니다: $O(E)$.
        -   따라서 총합은 $O(V + E)$가 됩니다.
    -   인접 행렬 사용 시: $O(V^2)$
        -   한 정점을 방문할 때, 연결된 이웃을 찾기 위해 $V$ 길이의 행 전체를 검사해야 합니다.
        -   모든 $V$개의 정점에 대해 이를 수행하므로 $V \times V = O(V^2)$가 됩니다.
-   **공간 복잡도:**
    -   방문 배열 : $O(V)$
    -   재귀 호출 스택(또는 명시적 스택) : 최악 $O(V)$
    -   **전체:** $O(V)$

### DFS의 활용 예시

-   **사이클 탐지(Cycle Detection)**  
    DFS 진행 시, 현재 경로 상에 이미 방문한 노드(스택에 있는 노드)를 다시 마주치면 그 지점에서 사이클이 있음을 판별할 수 있습니다.

-   **위상 정렬(Topological Sort)**  
    작업/과정 간 선후 관계가 존재하는 문제(예: 컴파일 의존성)에서, DFS로 각 노드의 탐색이 종료되는 역순으로 정점을 나열하면 위상 정렬 결과를 얻을 수 있습니다.

-   **미로 생성 및 해결**  
    DFS는 해가 존재하기만 하면 되거나, 모든 가능한 경로를 탐색해야 하는 경우에 적합합니다. (단, 최단 경로를 보장하지 않습니다.)

## 3. BFS (Breadth-First Search, 너비 우선 탐색)

### 3-1. 핵심 아이디어

-   **가까운 정점부터 차례대로, 레벨별로 탐색**
-   시작 정점에서 거리 1, 거리 2, 거리 3 ... 이런 식으로 "층(layer)" 순서로 탐색
-   **구현 방식:** 큐(queue) 사용
    -   BFS는 큐(Queue) 자료구조의 선입선출(FIFO) 특성을 활용, 먼저 발견된 노드를 먼저 방문함으로써 거리 순서대로 탐색이 진행됨

![[5.gif]][5.gif]

---

### 3-2. BFS 의사코드

```python
from collections import deque

def bfs(start):
    visited = set([start])
    queue = deque([start])

    while queue:
        u = queue.popleft()
        print(u)  # 방문 시 처리

        for v in graph[u]:
            if v not in visited:
                visited.add(v)
                queue.append(v)
```

---

### 3-3. BFS 시간·공간 복잡도

-   **인접 리스트 기준**
    -   **시간 복잡도:**  
        모든 정점과 간선을 한 번씩 방문  
        → $O(V + E)$
    -   **공간 복잡도:**
        -   방문 배열 : $O(V)$
        -   큐에 최대 $V$개까지 들어갈 수 있음 → $O(V)$
        -   **전체:** $O(V)$

### BFS의 장점

-   **BFS의 핵심 강점:** 최단 경로 보장

    -   가중치가 없는 그래프(Unweighted Graph)에서 BFS는 시작점으로부터 가장 적은 엣지를 거쳐 도달하는 **최단 경로(Shortest Path)**를 보장
        -   BFS가 거리 1인 노드를 모두 방문한 뒤에야 거리 2인 노드를 방문하기 때문

-   **응용:**
    -   소셜 네트워크의 '촌수 계산', 웹 크롤러(중요도 높은 페이지 우선 탐색), 최단 횟수로 퍼즐 풀기 등에 사용

## 4. DFS vs BFS 비교 & 활용

### 4-1. 탐색 방식 차이

| 항목           | DFS                               | BFS                                   |
| -------------- | --------------------------------- | ------------------------------------- |
| 자료구조       | 스택(Stack) / 재귀 호출           | 큐(Queue)                             |
| 방문 순서      | 한 방향으로 깊게, 막히면 되돌아옴 | 시작점에서 가까운 정점부터 레벨 순서  |
| 구현 난이도    | 재귀로 구현하면 간단              | 큐를 써야 해서 약간 더 코드가 길어짐  |
| 최단 거리 탐색 | ❌ (가중치 X, 최단경로 보장 X)    | ✅ (무가중 그래프에서 최단 경로 보장) |

---

### 4-2. 언제 DFS를 쓰면 좋은가?

-   모든 경우의 수 탐색 / 백트래킹
    -   예: 순열/조합, 미로 찾기(모든 경로), 게임 상태 탐색
-   연결 요소 개수 세기
-   재귀적으로 정의되는 구조(트리 등) 탐색에 직관적

---

### 4-3. 언제 BFS를 쓰면 좋은가?

-   **최단 거리** (모든 간선 가중치가 동일할 때)
    -   예: 미로에서 최소 이동 횟수, 최소 단계 수
-   "k단계 이내에 도달 가능한 노드"가 궁금할 때
-   레벨 순으로 데이터를 처리하고 싶을 때

### 4-4. 상황별 DFS/BFS 선택 가이드

#### 최단 거리를 찾아야 하는가?

-   **BFS 사용**
    -   가중치가 없는 그래프라면 최단 경로를 보장하는 BFS가 정답
    -   DFS는 목적지에 먼저 도달하더라도 돌아가는 경로일 수도 있으므로, 최단 경로라는 보장이 없음
-   **가중치가 있다면**
    -   다익스트라(Dijkstra) 알고리즘 등 가중치 고려 알고리즘을 사용해야 함

#### 그래프의 구조는?

-   **깊고 좁은 그래프**
    -   DFS가 더 적은 메모리로 효율적일 수 있음
    -   BFS는 큐에 많은 노드가 쌓여 비효율적일 수 있음
-   **넓고 얕은 그래프**
    -   DFS는 스택 깊이 초과(오버플로우) 우려가 적지만, 해(목적지)가 얕은 곳에 있다면 BFS가 더 빨리 찾을 수 있음

#### 메모리 제한이 있는가?

-   트리 등에서
    -   **DFS**: 최대 깊이(높이) $h$만큼의 메모리만 사용함
    -   **BFS**: 최악의 경우 트리의 최대 너비(지수적으로 증가할 수 있음)만큼 큐를 저장하므로, 메모리 사용량이 많아질 수 있음
-   **따라서 메모리가 매우 한정적이라면 DFS가 더 안전**

| 특징          | DFS (깊이 우선 탐색)              | BFS (너비 우선 탐색)             |
| ------------- | --------------------------------- | -------------------------------- |
| 사용 자료구조 | 스택 (Stack) / 재귀 (Recursion)   | 큐 (Queue)                       |
| 동작 원리     | Backtracking (깊게 파고들기)      | Layer-wise (양파 껍질 벗기듯)    |
| 시간 복잡도   | O(V+E) (인접 리스트 기준)         | O(V+E) (인접 리스트 기준)        |
| 공간 복잡도   | O(V) (트리의 높이에 비례)         | O(V) (트리의 너비에 비례)        |
| 최단 경로     | 보장하지 않음                     | 가중치 없는 그래프에서 보장      |
| 주요 활용     | 미로 생성, 위상 정렬, 사이클 탐지 | 최단 경로, 웹 크롤링, 네비게이션 |
| 메모리 효율   | 깊은 트리에서 효율적              | 얕은 트리에서 비효율적일 수 있음 |

## 5. 자료구조별 시간 복잡도 총정리 (Cheat Sheet)

### 5-1. 데이터 조작 및 접근 복잡도

> **(평균: 일반적인 경우 / 최악: 충돌이나 트리 치우침 등)**

| 자료구조       | 접근 (Access)        | 검색 (Search)   | 삽입 (Insertion) | 삭제 (Deletion)  | 공간 복잡도 |
| -------------- | -------------------- | --------------- | ---------------- | ---------------- | ----------- |
| 배열 (Array)   | O(1)                 | O(n)            | O(n)             | O(n)             | O(n)        |
| 연결 리스트    | O(n)                 | O(n)            | O(1) (헤드 기준) | O(1) (헤드 기준) | O(n)        |
