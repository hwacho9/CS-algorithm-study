# 2 주차: 해시 테이블(hash table), 트리(tree), 힙(heap)

## 자료구조의 효율적 탐색

## 1 주차 복습

![][image1] 시간 복잡도 (Big-O)

| 자료구조 | 특징 | 삽입/삭제/탐색시간 |
| :---- | :---- | :---- |
| 배열 (Array) | index로 접근이 빠르다 | O(n)/O(n)/O(1) |
| 배열 리스트 (ArrayList) | 순차탐색 | O(n)/O(n)/O(1) |
| 연결 리스트 (LinkedList) | 노드 연결 리스트 | O(1)/O(1)/O(n) |
| 스택 (Stack) | LIFO | O(1)/O(1)/O(n) |
| 큐 (Queue) | FIFO | O(1)/O(1)/O(n) |
| 데크 (Deque) | Double Ended Queue | O(1)/O(1)/O(n) |

\-\> 어느 자료구조를 사용해도 O(n)이 걸림  
\- \> 보다 효율적인 탐색을 위한 자료구조가 필요함

## 해시 테이블 (Hash Table)

- 키와 값 (Key Value System)을 이용, 자료를 정리  
- 배열 인덱스 기반 빠른 접근  
- JS의 Object, Python의 Dictionary, 

| ArrayList | Hash table |
| :---- | :---- |
| score\_list \= \[      { name: "A", score: 80 },     { name: "B", score: 89 },      { name: "C", score: 100 }, \]; | score\_list \= {    A: 80,    B: 89,    C: 100}; |
| 각 아이템을 순차 확인,  자료가 많을 수록 시간이 많이 걸림 O(n) | Key로 Value검색,  Constant time으로 검색 O(1), 삭제/삽입도 같음 |

### 해시 함수 (Hash function)

- **해시 함수(Hash function):** 입력된 키를 규칙에 따라 해시 코드로 변환하는 함수  
- Hash table은 Array구조를 베이스로 하지만, Hash function을 사용, 효율을 높인다   
- 키를 숫자 인덱스로 변환 (해시값), 인덱스에 값을 저장하는 방식

| 키(key) → 해시 함수(hash function) → 인덱스(index) → 값(value) |
| :---- |

![][image2]

**좋은 해시함수**

- 균등 분포: 키가 고르게 분포되어 **충돌**을 최소화  
- 효율성: 해시함수의 계산이 빠르고 효율적

### 해시 충돌(Collision)

- 해시 함수가 서로 다른 키를 동일한 해시값로 변환할때 발생하는 문제   
- 다른 키를 **같은 인덱스에 저장**하려고 할때 발생

#### **충돌 해결 방법**

##### 체이닝 (Chaining)

* 충돌한 인덱스 공간에 다른 배열을 추가  
* 충돌한 키-값 쌍을 연결리스트 (Linked list)로 저장

| score\_list \= {    A: 80,    B: 89,    \[(C: 100), (D:86)\]}; |
| :---- |

* 탐색:

| 키(key) → 해시 함수(hash function) → 인덱스(index) → 선형검색(LiearSearch)  \-\> 값 |
| :---- |

##### 개방주소법 (Open Addressing)

* 충돌 발생시 다른 빈 자리를 찾아 데이터 저장  
* 탐색:  
  * 선형 조사법 (Linear Probing)  
    * 바로 다음 인덱스를 확인해 빈 공간 탐색, 비어있지 않으면 찾을때까지 탐색  
  * 이차 조사법 (Quadratic Probing)  
    * 일정 간격(제곱)으로 증가하는 인덱스 확인   
  * 더블 해싱 (Double Hashing)  
    * 두번째 해시 함수 사용해 몇칸 이동할지 계산 후 탐색  
    * 연산이 오래걸림

❗️충돌시 다른 검색이 필요한 경우, 해시테이블의 검색은 O(1)이 아닐 수도 있다

### 해시 테이블의 장단점

* 장점  
  * 빠른 탐색/삽입 O(1)  
  * 간단 구현  
* 단점  
  * 해시 함수 설계 중요  
  * 충돌 발생 가능성

## 트리 (Tree)

- 노드들이 나무 가지처럼 연결된 계층적(hierarchy) 자료구조  
- 예) 폴더 구조, 조직도, 가계도

![][image3]

- 루트 노드 root node (1): 최상위 노드  
- 단말 노드 leaf node (4,15): 자식이 없는 노드  
- 크기 size : 트리에 포함된 노드의 개수   
- 깊이 depth: 루트 노드부터의 거리  
- 높이 height: 깊이 중 최댓값  
- 차수 degree: 각 노드의 자식방향 간선개수 

* 크기가 N일때, 기본적으로 전체간선 개수는 n-1

### 이진 탐색 트리 (Binary Search Tree)

- **이진탐색**이 가능하도록 구성된 트리구조  
- 각 노드는 최대 2개의 자식 노드를 갖는다

![][image4]

| 왼쪽 자식 노드 \< 부모 노드 \< 오른쪽 자식 노드 |
| :---- |

탐색: 

1. 루트 노드 방문해 비교  
2. 찾는 원소가 더 클 경우 오른쪽, 작을 경우 왼쪽 방문  
3. 찾을때까지 반복

✅ 한쪽 노드를 방문할 경우, 나머지 노드를 방문 하지 않아도 되기 때문에 효율이 좋다 (평균 O(log n))  
❗️트리가 한쪽으로 치우친 경우, 선형 구조가 되어 탐색이 O(n)이 될 수 있다

#### 이진 탐색 트리의 삭제

1. 단말 노드(Leaf Node)의 삭제  
- 삭제할 노드의 parent node가 삭제할 노드를 가리키지 않도록 한다

#### ![][image5]

2. 자식 노드(Child Node)가 하나인 node의 삭제  
- 삭제할 노드의 parent node가 삭제할 node의 child node를 가리키도록 한다

![][image6]

3. 자식 노드(Child Node)가 두개인 node의 삭제  
- 삭제할 노드의 오른쪽 자식을 삭제할 노드의 parent node가 가리키도록 하고 왼쪽자식을 오른쪽 자식이 가리키도록 한다

![][image7]

### 트리의 순회 (Tree Traversal)

- 트리 안의 **모든 노드를 체계적으로 방문하는 방법** (탐색x)

### ![][image8]

- 전위 순회 (pre-order traverse): 루트를 먼저 방문

| A \-\> B \-\> D \-\> E \-\> C \-\> F \-\> G |
| :---- |

 

- 중위 순회 (in-order traverse): 왼쪽 자식 방문후 루트 방문

| D \-\> B \-\> E \-\> A \-\> F \-\> C \-\> G |
| :---- |

- 후위 순회 (post-order traverse): 오른쪽 자식 방문후 루트 방문

| D \-\> E \-\> B \-\> F \-\> G \-\> C \-\> A |
| :---- |

### 트리의 장단점

* 장점:   
  * 빠른 탐색  
* 단점:  
  * 트리가 치우쳐져 있을 경우 탐색 효율이 떨어진다

## 힙 (Heap)

- 최댓값/최솟값을 찾아내기 위한 **완전이진트리 (complete binary tree)**

![][image9]

- **부모 \>= 자식 \-\> 최대 힙 (max heap)**  
  - 부모 노드의 키 값이 자식 노드의 키 값보다 크거나 같은 완전 이진 트리  
- **부모 \<= 자식 \-\> 최소 힙 (min heap)**  
  - 부모 노드의 키 값이 자식 노드의 키 값보다 작거나 같은 완전 이진 트리

✅ 힙에서는 가장 높은/낮은 우선순위를 가지는 노드가 항상 루트 노드이기때문에 최댓값이나 최솟값을 빠르게 계산

* **우선순위 큐 (priority queue)에 사용**

![][image10]

### 힙(Heap)과 배열(Array)

- 힙을 저장하는 표준 자료구조는 배열(Array)이다

![][image11]

* 힙에서의 부모 노드와 자식 노드의 관계  
  * 왼쪽 자식의 인덱스 \= (부모의 인덱스) \* 2  
  * 오른쪽 자식의 인덱스 \= (부모의 인덱스) \* 2 \+ 1  
  * 부모의 인덱스 \= (자식의 인덱스) / 2

### 힙의 삽입/삭제

**삽입: 노드 추가 후 위로 올림 (heapify up)**

1. 새로운 노드를 힙의 마지막 노드에 이어서 삽입한다.  
2. 새로운 노드를 부모 노드들과 교환해서 힙의 성질을 만족시킨다.

![][image12]

**삭제: 루트 제거 후 아래로 내림 (heapify down)**

1. 최대힙에서 최댓값은 루트 노드임으로 삭제  
2. 삭제된 루트노드에는 힙의 마지막 노드를 가져온다  
3. 자식노드와 비교해 큰 값과 교환해 힙의 성질을 만족시킨다.

![][image13]
